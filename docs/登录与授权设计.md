# SURS 登录与离线授权设计（v2）

## 1. 目标与结论

SURS 采用“签名激活卡 + 账号密码登录”的纯离线授权方式：

- 每家医院 1 组账号密码，按 60 家规模规划；接一家、发一家，不预建空账号。
- 首次运行显示“激活卡号 + 账号 + 密码”，已有有效授权时只显示“账号 + 密码”。
- 一张卡包含账号、PBKDF2 密码散列、有效天数、机构备注和签发时间。
- 授权从该电脑首次激活当刻起算，7 天为精确 `168` 小时，不是自然日。
- 同一张卡可以在不同电脑分别激活，但同一张卡在同一台电脑只能消费一次。
- 续期必须由发卡方签发新卡；新卡使用新卡指纹，可在同一账号下重新开启窗口。
- 软件不访问外网。签名、验签、登录、到期判断和状态保存全部在本机完成。
- 本方案不包含服务器、云端许可、联网心跳或远程停用能力。

> “纯离线”不等于“只能在医院内网运行”。程序文件与本地授权数据被整体拷走后，仍可能在另一台电脑运行；真正的院内锁定和提前停用需要未来的内网授权点。详见第 9 节。

## 2. 授权协议 v2

激活卡格式：

```text
SURS2.<base64url(规范UTF8载荷)>.<base64url(RSA-SHA256签名)>
```

规范载荷固定字段顺序：

```text
v=2
account=<账号>
salt=<PBKDF2盐，base64>
hash=<PBKDF2密码散列，base64>
days=<有效天数>
note=<机构备注，可省略>
issued=<签发UTC Tick>
```

约束：

- 账号仅允许 `A-Z a-z 0-9 . _ -`，长度 1–32。
- 天数 1–3650。
- 密码使用 PBKDF2-HMAC-SHA256，100,000 次迭代，16 字节盐，32 字节散列。
- 卡内只有密码散列，没有明文密码；明文密码只记录在甲方本地台账和交付单。
- `note` 为空时整行省略；解析允许 6 行或 7 行，并严格校验字段顺序。
- 解析拒绝空行、未知字段、重复字段、字段乱序、空值、错误版本和多余内容。
- 卡号粘贴时可含空格或换行，客户端会先去除所有空白再验签。
- 卡指纹为 `SHA-256(规范化卡号)` 的大写十六进制值，用于消费判定和台账对账。
- 授权卡必须是规范 base64url，拒绝“字节相同但文本不同”的变体，确保一张卡只有一个指纹。

签名私钥只由甲方授权管理员保管，绝不进入客户端发布包。软件源码只内置公钥。

## 3. 本机窗口与状态模型

首次激活时记录：

```text
firstUseUtc = 激活当刻
expiryUtc   = firstUseUtc + days × 24h
```

状态中的关键字段：

- `generation`：每次激活/续期生成的新状态代 GUID。
- `seq`：状态副本序列号，用于发现旧档回放。
- `deviceFingerprint = SHA-256(MachineGuid)`：绑定当前 Windows 安装。
- `activeCardFingerprint`：当前已安装卡的指纹，必须与 `license.card` 一致。
- `consumedCardFingerprints`：本机消费过的全部卡指纹，跨续期保留。
- `lastSeen`：本机见过的最大时间，用于发现系统时钟回拨。

状态副本：

1. 主副本：`%LOCALAPPDATA%\SURS\License\license.card` 与 `license.state`
2. 影子副本：`%PROGRAMDATA%\SURS\License\license.state`（尽力写入）
3. 当前用户注册表：`HKCU\Software\SURS\License\State`

主档缺失但影子存活时会恢复主档并保留原首次使用时间。每次变更尽量把同一代状态写入全部可写副本。

## 4. 防重置规则

启动、登录和激活执行以下规则：

1. 本机窗口未到期时，拒绝任何重新激活或换卡。
2. 某张卡在本机消费后永久拒绝该卡，即使授权已经过期。
3. 扫描任意可读状态代；只要同一机器指纹仍有未到期窗口，拒绝新卡激活。
4. 当前窗口已过期，且该卡未被本机消费时，允许新卡续期。
5. 机器指纹、当前卡指纹与状态记录必须匹配，否则停止运行。
6. 状态文件损坏、卡存在但状态全部缺失、主档回放旧序列时拒绝运行。
7. 当前时间早于所有副本中最新 `lastSeen` 超过 5 分钟时，判定时钟回拨并拒绝。
8. 不同机器放置同一张卡时，允许各自独立激活和计时；但把整机授权状态复制到另一台电脑会被机器指纹拦截。

已拦截的 L1 操作包括：改卡号、删单个副本、替换旧档、有效期内换卡、同一卡重复激活、把系统时间回拨。把主档、影子和注册表全部清除后，程序会把它视为新机器，这是纯离线方案无法根除的残余风险。

## 5. 启动与登录流程

1. `App.OnStartup` 调用 `StartupGate()`，不自动读取程序目录里的 `license.card`。
2. `Valid`：显示账号/密码登录页，同时展示授权起始时间、到期时间和剩余天数。
3. `NotActivated`：显示“激活卡号 + 账号 + 密码”，验证通过后才消费卡并开窗。
4. `Expired`：先显示到期信息，再进入续期页；输入新卡号、账号和密码后开新窗口。
5. `Tampered`、`ClockRollback`、`StorageError` 等状态：显示原因并退出，不进入主界面。
6. 登录失败统一提示“账号或密码错误”；密码错误不会先消费卡。
7. 每次启动都必须登录，不提供“记住我”或自动续签。

## 6. 甲方操作手册

### 6.1 生成并保管密钥

```powershell
dotnet run --project tools/SURS.LicenseTool -- init
```

默认密钥目录：

```text
%LOCALAPPDATA%\SURS.LicenseTool\.keys\
```

正式交付前必须重新生成正式密钥，把公钥替换到 `SURS.App/Services/License/EmbeddedLicenseKey.cs`，再重新发布软件。`private_key.pem` 严禁入库、发邮件或交医院；建议离线加密备份并限制管理员数量。

### 6.2 接一家、发一家

```powershell
dotnet run --project tools/SURS.LicenseTool -- issue `
  --note "某某医院" `
  --days 7 `
  --account hos01 `
  --out ".\交付\01-某某医院-交付单.txt" `
  --ledger ".\台账\60家台账.jsonl"
```

说明：

- `--note` 必填，用于机构识别和台账审计。
- 不写 `--account` 时自动按台账分配下一个 `hosNN`。
- 不写 `--password` 时自动生成 16 位强随机密码，排除易混字符。
- `--account` 可覆盖默认账号；`--password` 可指定密码。
- `--out` 生成完整交付单；如确需单独的卡号文本，可用 `--license-file`。
- 每次成功签发自动追加一支 JSONL 记录。

### 6.3 发放台账

默认台账：

```text
%LOCALAPPDATA%\SURS.LicenseTool\ledger.jsonl
```

每条记录包含：机构、账号、天数、签发时间、卡指纹、明文密码和保密警告。台账是本地授权管理员的交付依据，续期补发时需要查询原账号与密码，因此保留明文；卡内和客户端都不保存明文密码。

查询：

```powershell
dotnet run --project tools/SURS.LicenseTool -- list
dotnet run --project tools/SURS.LicenseTool -- list --account hos37
dotnet run --project tools/SURS.LicenseTool -- list --note "某某医院" --full
dotnet run --project tools/SURS.LicenseTool -- ledger list --ledger ".\台账\60家台账.jsonl"
```

### 6.4 验签与排查

```powershell
dotnet run --project tools/SURS.LicenseTool -- verify "<完整激活卡号>"
dotnet run --project tools/SURS.LicenseTool -- inspect "<完整激活卡号>"
```

`verify` 验签并显示账号、天数、备注、签发时间；`inspect` 只解析内容，并明确显示“签名未校验”。

### 6.5 续期

医院授权到期后，为同一账号签发**新卡**：

```powershell
dotnet run --project tools/SURS.LicenseTool -- issue `
  --note "某某医院" `
  --account hos37 `
  --days 7 `
  --out ".\续期\37-某某医院-续期交付单.txt" `
  --ledger ".\台账\60家台账.jsonl"
```

医院在续期页输入新卡号、账号和密码。新卡开新窗口；旧卡永久不能在该电脑再次使用。纯离线方案无法提前停用尚未到期的旧卡。

## 7. 60 家医院管理建议

- 使用一个受控的统一台账，例如 `D:\SURS-License\ledger.jsonl`，不要每家拆散。
- 建议固定 `hos01` 至 `hos60` 与医院清单的对应关系，续期沿用原账号。
- 机构名保持唯一；查询时同时用机构名和账号核对。
- 台账与私钥分开备份，限制访问人员；不要放进公开网盘或工单附件。
- 每次交付后运行 `list --account hosNN` 核对记录。
- 批量模式是可选增强能力，适合已有完整医院清单时使用；日常仍推荐“接一家、发一家”。

## 8. 自检与构建

```powershell
dotnet build SURS.sln -c Debug
dotnet run --project tools/SURS.LicenseSelfTest -c Debug
```

自检使用临时目录、假时钟和假机器指纹，不写真实授权路径或注册表。覆盖：

- 签发/验签、全字符篡改、规范 base64url、换行粘贴、空行/重复/未知/乱序字段拒绝；
- 首次使用计时、错误凭证不消费卡、正确/错误密码、时钟回拨、168 小时到期；
- 有效期内重复激活、同卡复用、到期后新卡续期；
- 主状态损坏、影子恢复、旧代回放、当前卡与状态不匹配；
- 同一卡在不同机器独立激活、整套状态复制到另一台电脑时拦截；
- 60 家台账累积与机构/账号过滤。

Release 单文件发布命令见根 `README.md`。

## 9. 防护边界与升级路径

### 9.1 本方案能拦截

- 修改卡号内容或自制未签名卡。
- 在有效期内重复激活、换卡刷新窗口。
- 到期后复用旧卡。
- 删除主状态、替换旧状态、保留旧代残片。
- 将系统时间回拨以延长使用。
- 把授权状态原样复制到另一台机器。

### 9.2 本方案不能承诺

- 重装 Windows 或更换整机后被识别为同一台机器。
- 有能力的逆向者修改程序、绕过校验或伪造运行环境。
- 把主状态、影子和注册表全部清除后阻止新窗口。
- 纯离线环境下提前停用一张已经发出的有效卡。
- 技术上锁死“只能在医院内网运行”；本方案只保证不依赖外部网络。

这些属于 L1 本地防护方案的真实边界，不应向甲方承诺为不可破解。

### 9.3 未来内网授权点升级路径

若甲方后续要求提前停用、集中审计、限制院内使用或机器迁移审批，可在医院内网部署授权点：

1. 客户端向院内授权点请求短期租约，不访问公网。
2. 授权点维护卡状态、机器状态和停用名单。
3. 客户端缓存短期租约，断网时只允许有限宽限窗口。
4. 发卡工具与授权点共享审计台账，签发和停用都有记录。
5. 保留现有离线卡作为应急回退，并明确回退时限。

该升级需要新增服务端组件，本期不实现。

## 10. 数据保护与运维

- 软件不调用 HTTP、WebSocket、邮件、遥测或外部时间服务。
- 台账和交付单含明文密码，必须按敏感文件管理。
- 私钥丢失后无法为现有客户端签发兼容新卡，只能更换公钥并重新发布。
- 重新运行 `init --force` 会使旧公钥签发的卡全部失效。
- 系统时间被回拨后，先校准真实时间；回拨触发后不能靠简单重启解除。
- 授权文件与日志均保存在本地。医院迁移电脑应联系甲方重新发卡或走未来内网授权点流程。
