# SURS 登录与离线授权设计（v2）

## 1. 目标与结论

SURS 采用“激活卡 + 账号密码登录”的纯离线授权模式：

- 每家医院 1 组账号密码，按 60 家规模规划；接一家、发一家，不预建空账号。
- 一张卡包含账号、PBKDF2 密码散列、有效天数、机构备注和签发时间。
- 授权从**该电脑首次激活当刻**起算，7 天为精确 `168` 小时，不是自然日。
- 同一张卡可以在不同电脑分别激活，但**同一张卡在同一台电脑只能消费一次**。
- 续期必须由发卡方签发新卡；新卡使用新卡指纹，可让同一账号重新开始一个窗口。
- 软件本身不访问外网。签名、验签、账号登录和到期判断全部在本机完成。
- 本方案不包含服务器、云端许可、联网心跳或远程停用能力。

> “纯离线”不等于“只能位于医院内网”。程序文件与本地授权数据被整体拷走后，仍可能在另一台电脑运行；真正的院内部署锁定与提前停用需要未来的内网授权点。详见第 9 节。

## 2. 授权协议 v2

卡号格式：

```text
SURS2.<base64url(规范UTF8载荷)>.<base64url(RSA-SHA256签名)>
```

规范载荷固定字段顺序：

```text
v=2
account=<账号>
salt=<PBKDF2盐，base64>
hash=<PBKDF2密码散列，base64>
days=<有效天数>
note=<机构备注，可省略>
issued=<签发UTC Tick>
```

约束：

- 账号仅允许 `A-Z a-z 0-9 . _ -`，长度 1–32。
- 天数 1–3650。
- 密码使用 PBKDF2-HMAC-SHA256，100,000 次迭代，16 字节盐，32 字节散列。
- 卡内只有密码散列，没有明文密码；明文密码只记录在发卡方本地台账和交付单中。
- 解析拒绝空行、未知字段、重复字段、字段乱序、错误版本和多余内容。
- 卡号粘贴时可包含空格或换行，客户端会先去除所有空白再验签。
- 卡指纹为 `SHA-256(规范化卡号)` 的小写十六进制值，用于本机消费判定和台账对账。

签名私钥只由甲方授权管理员保管，绝不进入软件发布包。软件源码只内置公钥。

## 3. 本机窗口与状态模型

首次激活时记录：

```text
firstUseUtc = 激活当刻
expiryUtc   = firstUseUtc + days * 24h
```

此后到期时间不再变化。启动、登录和激活会用当前时间与以下记录比较：

- `lastSeen`：本机曾经见过的最大时间，用于阻止系统时钟回拨。
- `deviceFingerprint = SHA-256(MachineGuid)`：绑定当前 Windows 安装。
- `cardFingerprint`：当前卡指纹。
- `consumedCardFingerprints`：本机已消费过的全部卡指纹，跨续期保留。
- `generation`：每次激活生成的新状态代 GUID，多个副本使用同一代。

状态副本：

1. 主副本：`%LOCALAPPDATA%\SURS\License\license.card` 与 `license.state`
2. 影子副本：`%PROGRAMDATA%\SURS\License\license.state`（尽力写入，通常需管理员权限）
3. 当前用户注册表：`HKCU\Software\SURS\License\StateV2`

状态变更时，主副本和可写的加固副本写入同一代内容。删除主副本但影子仍与当前卡匹配时，会自动恢复主副本并保留原首次使用时间。

## 4. 防重置规则

激活和启动执行以下规则：

1. 本机窗口未到期时，拒绝任何重新激活或换卡。
2. 某张卡在本机消费后永久拒绝该卡，即使授权已经过期。
3. 扫描任意可读状态代；只要同一 `deviceFingerprint` 仍有未到期窗口，拒绝新卡激活。
4. 当前窗口过期且该卡未被本机消费时，允许新卡续期。
5. 状态文件损坏、主状态缺失且无可恢复副本、当前卡与状态不匹配时，拒绝运行。
6. 当前时间早于所有副本中最新 `lastSeen` 超过 5 分钟时，判定时钟回拨并拒绝运行。
7. 不同机器放置同一张卡时，允许各自独立激活和计时。

删除单一副本、替换旧状态、有效期内换卡等 L1 操作会被拦截。把主副本、影子和注册表全部清除后，程序会把它视为一台新机器，这是纯离线方案无法根除的残余风险。

## 5. 启动与登录流程

1. `App.OnStartup` 调用 `StartupGate()`。
2. `Valid`：显示账号/密码登录页，不展示卡号原文。
3. `NotActivated`：显示激活卡号、账号、密码输入页。
4. `Expired`：先提示到期原因，再进入“新卡续期并登录”页面；旧卡和旧密码不能登录。
5. `Tampered`、`ClockRollback`、`StorageError` 等状态：显示原因并退出，不允许进入登录页。
6. 首次激活会先在**不消费卡号**的前提下校验账号密码，校验通过后才写入首次使用时间和消费记录。
7. 每次启动都需要手动登录，不实现“记住我”或自动续签。

登录失败统一显示“账号或密码错误”，不泄露账号是否存在。篡改、回拨、重复激活和失败登录写入本地日志：

```text
%LOCALAPPDATA%\SURS\Logs\
```

## 6. 发卡工具与台账

### 6.1 生成正式密钥

正式交付前在一个受控离线环境执行一次：

```powershell
dotnet run --project tools/SURS.LicenseTool -- init
```

私钥默认位于：

```text
%LOCALAPPDATA%\SURS.LicenseTool\.keys\private_key.pem
```

然后运行：

```powershell
dotnet run --project tools/SURS.LicenseTool -- pubkey
```

把输出的公钥替换到 `SURS.App/Services/License/EmbeddedLicenseKey.cs`，重新发布软件。私钥必须单独离线备份，严禁提交仓库或随软件发放。

仓库当前内置的是演示公钥；演示私钥不进入仓库。正式上线时必须重新生成密钥对，避免使用演示密钥。

### 6.2 为一家医院发卡

```powershell
dotnet run --project tools/SURS.LicenseTool -- issue `
  --note "某某医院" `
  --days 7 `
  --out ".\交付单\某某医院.txt"
```

默认行为：

- 账号按台账自动生成：`hos01`、`hos02`……；可用 `--account` 覆盖。
- 密码自动生成 16 位强随机密码；可用 `--password` 指定至少 12 位密码。
- `--gen-password` 可显式要求自动生成密码，不能和 `--password` 同时使用。
- 卡号和账号交付给医院；密码同时写入本地台账和交付单。
- 台账默认追加到 `%LOCALAPPDATA%\SURS.LicenseTool\ledger.jsonl`，可用 `--ledger` 改为审计目录中的文件。

台账是不含历史删除操作的追加式 JSONL，一条记录包含机构、账号、天数、签发时间、卡指纹和明文密码，并带保密警告。台账是补发、续期和审计的唯一本地依据，必须限制访问权限并单独备份。

### 6.3 查询 60 家台账

```powershell
dotnet run --project tools/SURS.LicenseTool -- list
dotnet run --project tools/SURS.LicenseTool -- list --account hos37
dotnet run --project tools/SURS.LicenseTool -- list --note "某某医院"
```

### 6.4 验证与排查

```powershell
dotnet run --project tools/SURS.LicenseTool -- verify "<完整卡号>"
dotnet run --project tools/SURS.LicenseTool -- inspect "<完整卡号>"
```

`verify` 验签并显示账号、天数、备注、签发时间；`inspect` 只解析内容，明确显示签名“未校验”。

### 6.5 续期

医院授权到期后，使用**新卡**续期：

1. 按第 6.2 节为同一账号签发新卡（可继续使用原账号或按甲方规则指定账号）。
2. 医院在到期提示后的续期页输入新卡、账号和新密码。
3. 新卡消费后生成新状态代，窗口从本次续期激活当刻重新计算。
4. 旧卡永久不可在该电脑再次使用，历史消费指纹继续保留在状态中。

不能通过把系统时间改回去、重复粘贴旧卡或删除单个状态副本获得新窗口。

## 7. 60 家医院的建议操作

- 使用一个受控台账文件，例如 `D:\SURS-License\ledger.jsonl`，不要按医院拆分。
- 交付前为每家生成一个 `--out` 文件，作为签字/邮件附件。
- 交付单中保留机构名、账号、密码、完整卡号、签发时间与卡指纹。
- 台账和密钥分开备份：台账可给授权管理员；私钥只交给最少人员。
- 每次交付后立即执行 `list --account hosNN` 核对记录。
- 若账号被指定覆盖，仍建议机构名唯一，续期按机构名和账号双重检索。
- 60 家规模无需服务器；本工具和程序都可在完全断网电脑上运行。

## 8. 测试与构建

```powershell
dotnet build SURS.sln -c Debug
dotnet run --project tools/SURS.LicenseSelfTest -c Debug
```

自检使用临时目录、假时钟、假机器指纹，并关闭注册表镜像，不写真实授权路径或真实注册表。覆盖：

- 签发/验签、逐字符篡改、base64url、换行粘贴、未知/重复/空行拒绝；
- 首次使用计时、账号密码、时钟回拨、168 小时到期；
- 有效期内重复激活、同卡复用、续期新卡、删除主副本后的影子恢复；
- 跨代未到期窗口、只剩旧代残留；
- 同一卡在不同机器独立激活；
- 连续签发 60 家与台账过滤。

Release 单文件发布仍使用 README 中的 `dotnet publish` 命令。

## 9. 防护边界与升级路径

### 9.1 本方案能拦截

- 修改卡号内容或自制未签名卡。
- 在有效期内重复激活、换卡刷新窗口。
- 到期后复用旧卡。
- 删除主状态、替换旧状态、仅保留旧代副本。
- 将系统时间回拨以延长使用。
- 把授权状态原样复制到另一台机器（机器指纹不匹配）。

### 9.2 本方案不能承诺

- 重装 Windows 或更换整机后被识别为同一台机器。
- 有能力的逆向者修改程序、绕过校验或伪造运行环境。
- 把主状态、影子和注册表全部清除后阻止新窗口。
- 纯离线环境下提前停用一张已经发出的有效卡。
- 技术上锁死“只能在医院内网运行”；本方案只保证不依赖外部网络。

这些属于 L1 本地防护方案的真实边界，不应向甲方承诺为不可破解。

### 9.3 未来内网授权点升级路径

若甲方后续要求提前停用、集中审计、限制院内使用或机器迁移审批，可在医院内网部署授权点：

1. 客户端启动时向**院内授权点**请求短期租约，仍然不需要访问公网。
2. 授权点维护卡状态、机器状态和停用名单。
3. 客户端缓存短期租约，断网时只允许有限宽限窗口。
4. 发卡工具与授权点共享审计台账，签发和停用都留下记录。
5. 保留现有离线卡作为应急回退，但明确回退时限。

该升级需要新增服务端组件，本期不实现。

## 10. 数据保护与运维注意事项

- 软件不调用 HTTP、WebSocket、邮件、遥测或外部时间服务。
- 台账含明文密码，必须按敏感文件管理；不要放进 Git、共享盘公开目录或工单附件。
- 私钥丢失后无法为现有客户端签发兼容新卡，只能更换公钥并重新发布软件。
- 重新运行 `init --force` 会使旧公钥签发的卡全部失效。
- 修改系统时间后，应先把时间校准到真实时间；回拨触发后不能通过简单重启恢复。
- 授权文件与日志均保存在本地。医院如需迁移电脑，应联系甲方重新发卡或按未来内网授权点流程审批。
