# SURS 60 家医院交付指引

## 1. 原则

- 每家医院 1 组账号密码和 1 张 7 天激活卡。
- 接一家、发一家；不预建空账号。
- 授权自该院电脑首次激活当刻起算 168 小时。
- 续期必须发新卡，沿用原账号或按甲方规则指定账号。
- 台账含明文密码，只允许授权管理员保管。

## 2. 交付前准备

1. 重新生成正式 RSA 密钥对。
2. 将正式公钥替换到 `SURS.App/Services/License/EmbeddedLicenseKey.cs`。
3. 重新发布 `SURS.App.exe` 并校验运行。
4. 将统一台账放到受控目录，例如 `D:\SURS-License\ledger.jsonl`。
5. 将私钥放在独立离线介质，严禁与交付包一起发送。

## 3. 单家发卡

```powershell
dotnet run --project tools/SURS.LicenseTool -- issue `
  --note "某某医院" `
  --days 7 `
  --account hos01 `
  --out ".\交付\01-某某医院-交付单.txt" `
  --ledger "D:\SURS-License\ledger.jsonl"
```

- 不写 `--account` 时自动分配 `hos02`、`hos03`……
- 不写 `--password` 时自动生成 16 位强随机密码。
- 交付单包含激活卡号、账号、密码、有效天数、签发时间和卡指纹。
- 台账自动追加一条 JSONL 记录。

## 4. 批量模式

适合已经拿到完整医院名单时使用。名单每行：

```text
某某医院
某某医院2,hos02
某某医院3,hos03,指定密码
```

命令：

```powershell
dotnet run --project tools/SURS.LicenseTool -- batch `
  --hospitals "医院名单.txt" `
  --days 7 `
  --out ".\医院交付包" `
  --app-exe ".\Publish\SURS.App.exe" `
  --ledger "D:\SURS-License\ledger.jsonl"
```

输出：

- 每家医院一个文件夹，包含 `SURS.App.exe`（可选）、`license.card` 和 `交付单.txt`。
- `交付清单.csv`。
- 统一 JSONL 台账。

客户端**不会自动读取**文件夹中的 `license.card`。医院首次启动时仍需手工输入交付单上的激活卡号、账号和密码。`license.card` 仅作为卡号备份和甲方复核资料。

## 5. 交付检查

每次交付后运行：

```powershell
dotnet run --project tools/SURS.LicenseTool -- list --account hos01 --ledger "D:\SURS-License\ledger.jsonl"
dotnet run --project tools/SURS.LicenseTool -- verify "<完整激活卡号>"
```

确认：

- 机构名和账号对应正确。
- 有效天数为 7。
- 卡指纹与交付单一致。
- 验签结果为有效。

## 6. 续期

到期后为该院签发新卡，不要重复交付旧卡：

```powershell
dotnet run --project tools/SURS.LicenseTool -- issue `
  --note "某某医院" `
  --account hos01 `
  --days 7 `
  --out ".\续期\01-某某医院-续期交付单.txt" `
  --ledger "D:\SURS-License\ledger.jsonl"
```

医院在新续期页输入新卡号、账号和密码。旧卡在同一台电脑上永久不可复用。

## 7. 保密与边界

- 台账、交付单和交付清单含明文密码，严禁外传。
- 私钥泄露等于整个发卡体系失守。
- 纯离线无法提前停用已发出的有效卡。
- 重装整机、换新机、逆向破解不属于 L1 防护范围。
- 若需提前停用或院内限制，应升级为内网授权点。
